## H2 表结构维护 · 增删改查修复

**Bug 1（用户报"修改表结构时字段开始都是空的"）**：
`H2DataController.tableStructure()` 返回的 `columns[]` 元素经过 `toCamelCaseKeys()` 后字段是
`columnName`/`typeName`/`characterMaximumLength`/`isNullable`/`columnDefault`/`isIdentity`，
而前端 `DbManageView.vue` 的 `colColumns` 期望的是 `name`/`type`/`maxLen`/`nullable`/`defaultValue`/`autoInc`。
前后端 6 个字段全部对不上 → 📐 表结构 Tab 渲染时列头是中文但单元格全空。
**修复**：controller 内新增投影步骤，把驼峰化的 columns 重命名为前端友好字段（name/type/maxLen/...）。
DDL 仍用原始 columns 生成，不受影响。

**Bug 2（前端兜底加固）**：
- `showAddModal` 用 `columnNames`（大写下划线如 `USERNAME`）初始化 `editForm.value[col] = ''`，
  但模板 v-model 用 `col.dataIndex`（驼峰如 `username`）。改用驼峰初始化。
- `showEditModal` 不过滤 `__row_index` 直接 `{ ...record }`，新增过滤 + 仅保留模板渲染的列。
- `handleDelete` fallback 用 `Object.keys(record)[0]` 时可能拿到 `__row_index`，改成过滤后取首列。
- `handleSave` 用 `delete data[k]` 改用 `continue`（更显式），且过滤 `__row_index`/`__actions`。
- 把 `toCamel` 提到模块顶部 `toCamelName`，避免 showEditModal/handleDelete 各自重复定义。

**Bug 3（后端 0 行影响静默成功）**：
`updateRow`/`deleteRow` 之前只调 `jdbc.update()` 不检查返回值，主键错误或记录不存在时仍返回 "更新成功" / "删除成功"。
**修复**：检查 `affected`，0 行时返回 `Result.error(404, "未找到对应记录...")`。
验证：PUT id=99999 → code=404；DELETE id=99999 → code=404；正常 CRUD 仍 200。

**前端 build / 类型检查**：vue-tsc + vite build 全过。
