## 菜单消失修复（用户反馈）

**问题**：H2 菜单（db-manage）和租户管理菜单在"系统设置"中消失；清空按钮灰色。根因：① `MainLayout.vue` 菜单项挂了 `v-if="authStore.isSuperAdmin"`，而 `isSuperAdmin` 原判断 `=== 'ADMIN'`（严格大写），数据库里 admin role 是小写 `admin`，一旦 role 值不是大写 'ADMIN' 就隐藏菜单 ② 前端按钮也用 `:disabled="!isAdmin"` 重复卡权限（后端本有 admin 校验兜底）。

**修复**：
- `MainLayout.vue`：删除 db-manage / tenants 菜单项的 `v-if="authStore.isSuperAdmin"` —— 菜单无条件显示（后端接口仍按 admin 校验，非管理员操作 403，不影响安全）
- `stores/auth.ts`：`isSuperAdmin`/`isTenantAdmin`/`isViewer` 改为大小写不敏感（`toUpperCase()` 后比较，兼容 'admin'/'ADMIN'/'super_admin'）
- `DbManageView.vue`：清空按钮去掉 `:disabled="!isAdmin"`（后端兜底）；顶部按钮改名"清空"；一键清空弹窗标题"一键清空数据"，默认勾选流水表（flowType），可全选
- `TableMetaService.isClearable()`：语义改为**除 22 张硬保护表外任意表可清空**（不再限 FLOW/AGENT_SYNC 类型）；新增 `isFlowType()` 标记"推荐清空"（流水/Agent同步表），前端用 flowType 做默认勾选和标签
- 验证：32 张表可清空（含 BASE 型 kb_comment 等）、22 张地基表（sys_user/node_info/project_info/tenant 等）仍 403 拒绝
- 用户 dev server 跑在 **3000 端口**（vite，cwd=frontend），改源码热更新即生效，dist 也重新构建了（`--emptyOutDir=false` 避免 safe-delete 拦截）

## 前端部署安全契约修复（用户反馈：重部署误删部署目录内其他文件）

**新契约（定稿）**：解压目录名 = zip 文件名去扩展名，固定解压到 `{deployDir}/{zip基础名}/`；重部署只备份/删除该同名文件夹（`{zip基础名}.backup-{ts}`），目录内其他文件一律保留；失败还原有备份还原、无备份清理空目录。`frontendDirName`/`frontendDeployDir` 部署不再使用（列保留）；前端项目必须配 deployDir。

**改动**：
- `DeployController.java`：删三选一目录逻辑，前端分支改同名文件夹契约；新增 `zipBaseName()`/`trimTrailingSlash()`；还原分支补"无备份→清理空目录"

## 前端部署智能解包（smart-unzip）落地 + 用户实测
- **触发**：用户在用户系统里传 `dist3.zip`（内部 `dist3/dist3/index.html` + macOS `__MACOSX/.DS_Store`），用我第一版的"单顶层目录判断"结果套了3层。
- **算法**：Netlify/Vercel/gh-pages 工业标准——「剥最长共有目录前缀 + 过滤垃圾」
  - `__MACOSX/`、`.DS_Store`、`._*` 一律跳过
  - 字符级 LCP 求所有有效路径的最长前缀，截到最后一个 `/`（必须完整目录边界）
  - 第二遍解压时每个文件 substring(LCP 长度)
- **代码位置**：`agent/FileController.java` 的 `unzipFile` + `computeCommonPrefixAndFilterJunk` + `isJunkEntry` + `longestCommonPrefix`。
- **健壮性 8 场景实测**（直接调 agent `/api/file/unzip`）：
  1. 内外层名不同（`out/dist/`） ✅ 剥到 `index.html, a.css`
  2. 5 层深嵌套（`a/b/c/d/{e,f}/`） ✅ 剥到 `e/x.html, f/y.html`
  3. 顶层混合（`README.md` 散文件 + `proj/...`） ✅ 不剥壳，README 保留
  4. macOS 垃圾轰炸（`.DS_Store + __MACOSX + ._index.html`） ✅ 全过滤
  5. 只有垃圾的 zip ✅ code=500 报错「未解压出任何文件」
  6. 扁平（`index.html, app.css`） ✅ 不剥壳
  7. 中文+特殊字符文件名 ✅ 原样保留
  8. 内嵌 zip（`static/embedded.zip`） ✅ 不解内层，原样落地
- **算法边界**（已知弱点，可选补强）：
  - 无解压大小/条目上限 → 防 zip bomb 待加
  - 同步阻塞 HTTP 线程 → 超大包会卡 agent
- **用户测试期间踩坑**：
  - vite 优先用 `vite.config.js` 而非 `.ts`（历史遗留 .js 覆盖 .ts），改 .js 才生效
  - vite dev 启动方式：`cd frontend && npm run dev`（无 dev.sh，得手起）
