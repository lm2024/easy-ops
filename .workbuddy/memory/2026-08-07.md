## 环境操作
- 启动 docker agent：`cd easy-ops/backend && docker compose up -d agent-1 agent-2 agent-3`（3 个容器 ops-agent-1/2/3，映射 2123/2124/2125）。
- 镜像从 `agent/docker/` 构建（含 procps 修复、entrypoint 每次启动覆盖 /app/data/agent.jar）。
- agent 通过 `host.docker.internal:8081/api` 连 server；server 由用户本机启动，未起时日志 Connection refused 属正常，server 上线后自动恢复在线。
- 用户自管 server 与前端；agent 归我（docker）管。

## 白名单自动登录功能（新增）
- 需求：agent/自动化调试被登录验证码卡住，要求"白名单=免登录"，直接拿已登录 token。
- 实现：`SystemController` 新增 `POST /api/auth/auto-login`，携带白名单 key（请求体 key 或头 X-Auto-Login-Key）直接返回 token，跳过账号密码+验证码。复用现有 token 生成/缓存逻辑（权限与正常登录一致，默认 admin）。
- 安全：默认全部关闭。配置 `easyops.auth.*`（application.yml），对应环境变量 `AUTO_LOGIN_ENABLED` / `AUTO_LOGIN_USERNAME` / `AUTO_LOGIN_WHITELIST`（逗号分隔）。开关关/白名单空/key不匹配 → 一律 403。
- 放行：`AuthInterceptor.preHandle` 增加了 `/auth/auto-login` 跳过鉴权（否则自己被拦死循环）。
- 文档：写入 `AGENTS.md` 新增「自动化/agent 自动登录」章节（配置表 + curl 示例 + 安全边界）。
- 验证：用 Corretto JDK8 打包，隔离端口 8099 起临时实例（AUTO_LOGIN_ENABLED=true, WHITELIST=test-key），四种场景（正确key/错误key/无key/头方式）全部符合预期；已停实例并清理 /tmp/easyops-test-data。
- 注意：用户正在跑的 8081 server 是旧 jar，需重启为新 jar 并加 3 个环境变量才生效。本机 curl 走 127.0.0.1 需 `--noproxy '*'`（环境有 HTTP_PROXY）。
