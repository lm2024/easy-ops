# H2 表结构维护完善 · 设计方案与落地记录

> 日期：2026-08-18
> 状态：已实现并通过 API 自测
> 涉及模块：Server (`/db` 接口) + 前端 (`DbManageView`) + 配置 (`application.yml`)

## 一、背景与问题

原 `DbManageView.vue` 前端硬编码 37 张表的分类元数据（`TABLE_META`），但实际库中有 **54 张表**（52 schema + 2 动态建表），约 20 张表无法识别落入"其他"分组，包括：

- **Nginx 流量表** 8 张（`nginx_minute_stat` / `nginx_ua_stat` / `nginx_referer_stat` / `nginx_ip_stat` / `nginx_request_sample` / `nginx_whitelist` 等）
- **Agent 同步表**（`node_config_snapshot` / `node_script_snapshot` / `node_transfer_application` 等）
- **脚本分发表**（`global_script_*` / `project_script_file` / `script_distribute_record` 等）
- **租户表**（`tenant` / `tenant_user`）

三个问题根因：
1. **分类元数据在前端硬编码**：后端加表 → 前端漏登记 → 永远"未识别"（架构问题）
2. **流水表清单三处维护、互相脱节**：`application.yml table-retain-days` / `DataCleanupScheduler.buildTasks()` / `H2DataController.cleanupAll()` 硬编码列表
3. **无"一键清空数据"能力**：只有按保留天数清理，不能全清

## 二、设计：单一事实来源

### 2.1 表元数据收敛到 yml（`easyops.data.table-meta`）

新增配置段（`application.yml`）：

```yaml
easyops:
  data:
    table-meta:
      categories:      # 分类 key -> label/icon，前端分组渲染
        nginx:  { label: "Nginx 流量", icon: "🌐" }
        script: { label: "脚本分发",   icon: "🧩" }
        # ...
      tables:          # 表名(小写) -> label/category/type/source
        sys_user:        { label: "系统用户", category: user,  type: BASE }
        nginx_minute_stat: { label: "分钟统计", category: nginx, type: FLOW, source: nginx }
        node_config_snapshot: { label: "节点配置快照", category: config, type: AGENT_SYNC, source: agent }
        # ...
```

**type 四分类**（表"识别"的核心）：
| type | 含义 | 可清空 | 示例 |
|------|------|--------|------|
| `BASE` | 基础数据表（用户/节点/项目/租户/配置） | ❌ | `sys_user` `node_info` `project_info` `tenant` |
| `CONFIG` | 配置/状态表（探针/锁/策略） | ❌ | `scheduler_lock` `project_health_probe` |
| `FLOW` | 流水表（日志/统计/记录） | ✅ | `operation_log` `nginx_minute_stat` `deploy_record` |
| `AGENT_SYNC` | Agent 同步上报表 | ✅ | `node_config_snapshot` `node_script_snapshot` |

`source` 字段标记数据来源（`agent` / `nginx` / `script` / `kb`），用于识别"agent 同步过来的表"。

### 2.2 自动识别兜底（未登记表）

`TableMetaService` 扫描 `INFORMATION_SCHEMA`，未在 yml 登记的表按命名规则启发式归类：
- 前缀 `nginx_` → Nginx 流量；`kb_` → 知识库；`node_` → 节点；`tenant*` → 租户；`global_script_`/`script_` → 脚本分发
- 后缀 `_log`/`_record`/`_stat`/`_event`/`_sample` → FLOW；`_snapshot`/`*_sync` → AGENT_SYNC；`_config`/`_lock`/`_policy`/`_probe`/`_rule` → CONFIG
- 仍无法归类 → `category=其他`，**`recognized=false`**，前端显示 ⚠️"待归类"角标，提示管理员去 yml 补充
- 兜底结果**不回写 yml**（yml 是手维护源），只在响应中标注

### 2.3 可清空保护清单（硬编码兜底）

即使 yml 误配为 FLOW/AGENT_SYNC，以下表也**禁止清空**（`TableMetaService.PROTECTED_TABLES`）：
`sys_user` `node_info` `project_info` `version_package` `tenant` `tenant_user` `user_project_relation` `sys_config` `alarm_config` `self_heal_policy` `scheduler_lock` `kb_document_lock` `nginx_source_whitelist` `nginx_traffic_alarm_rule` `nginx_access_source` `project_config_file` `project_log_profile` `project_health_probe` `project_script_file` `global_script_file` `kb_category` `kb_document`

## 三、接口设计

### 3.1 `/db/tables` 升级

原返回 `[{tableName}]`，现返回完整元数据（`?withRowCount=true` 可统计行数）：

```json
{
  "tableName": "nginx_minute_stat",
  "label": "分钟统计",
  "category": "Nginx 流量",
  "categoryKey": "nginx",
  "icon": "🌐",
  "type": "FLOW",
  "source": "nginx",
  "retainDays": 2,          // 联动 cleanup.table-retain-days / nginx minute-retain-days
  "rowCount": 154320,
  "clearable": true,        // FLOW/AGENT_SYNC 且不在保护清单
  "recognized": true
}
```

### 3.2 新增清空接口（全部 admin-only）

| 接口 | 说明 |
|------|------|
| `POST /db/table/{tableName}/clear?confirm=true` | 清空单表 |
| `POST /db/clear-batch` `{tables:[...], confirm:true}` | 批量清空 |
| `POST /db/clear-all-flow` `{confirm:true}` | 一键清空所有可清空流水表 |
| `GET /db/clearable-tables` | 可清空表清单（前端弹窗用） |

**实现细节**：
- 非 FLOW/AGENT_SYNC 表直接 403（保护清单兜底）
- `confirm=true` 必传（防误触）
- `nginx_minute_stat` / `monitor_snapshot` 大表走**分批删除**（`batchSize=10000`），避免长事务锁库
- 返回 `deleted` 行数 + `compactHint: true`（提示 H2 文件不立即缩小，建议重启触发 COMPACT 或 `scripts/rescue-h2.sh`）
- 清空后写 `operation_log`（module=DB，action=CLEAR_TABLE/CLEAR_BATCH/CLEAR_ALL_FLOW）——操作审计闭环

### 3.3 权限收紧（重要安全修复）

原 `/db/**` 在 `WebConfig` 中是 **excludePathPatterns（免登录）**，任何请求可访问。本次：
1. 从 WebConfig exclude 中移除 `/db/**` → 走 AuthInterceptor 统一登录校验（未登录 401）
2. `H2DataController` 所有**写操作**（增/删/改/清空/导入/导出）加 `isAdmin()` 校验（403）
3. 只读查询（列表/结构/数据）登录即可
4. 前端菜单本就 `isSuperAdmin` 门控 + 清空按钮 admin-only 显示

### 3.4 `/db/cleanup` 对齐单一来源

原硬编码 13 张表的 `cleanupAll()` 改为从 `tableMetaService.listClearableTables()` 读取，保留天数联动 `table-retain-days` / `nginx minute-retain-days`，自动识别时间列（create_time/bucket_time/ts/expire_time）。

> 说明：`DataCleanupScheduler`（定时调度）保留 mapper 绑定式任务（每表有专属 deleteBefore SQL + 特殊分批/级联逻辑），未强行配置化——它与 `/db/cleanup` 职责不同，后者是纯表名清单。

## 四、前端改造（`DbManageView.vue`）

1. **删除 `TABLE_META` / `CATEGORY_ORDER` 硬编码**，完全消费后端 `/db/tables` 返回的元数据 → 后端加表零前端改动
2. 分组标题显示"可清空 N"徽标；流水表带 🧡/橙色"流水"标签，AGENT_SYNC 带蓝色"Agent同步"标签
3. 未识别表 ⚠️"待归类"角标（hover 提示去 yml 登记）
4. **清空数据按钮**（仅可清空表 + admin）：点击 → Modal 二次确认 → **要求输入表名** → 确认后调用 clear 接口 → 显示删除行数 + compactHint
5. **顶部"清空流水表"按钮**（admin）：弹窗列出全部可清空表（带行数/类型），勾选或全选，批量/全量清空，逐表返回结果明细
6. 大表警告：`rowCount > 10w` 显示"建议直接清空而非全量浏览"横幅
7. 表结构 Tab 增加元数据展示（分类/类型/来源/保留天数/可清空/识别状态）
8. 非 admin 的"新增/编辑/删除/导入"按钮全部禁用

## 七、后续建议

- **生产部署**：需重启 server 生效（涉及 WebConfig 鉴权变更 + 新 Service Bean）
- **新增流水表**：只需在 `application.yml` `easyops.data.table-meta.tables` 加一行（type=FLOW/AGENT_SYNC），定时清理、手动清理、一键清空、前端展示四处自动生效
- **H2 文件膨胀**：清空后文件不自动缩小，可配置 `easyops.data.cleanup.auto-restart=true` + 外部守护自动重启，或用 `scripts/rescue-h2.sh`
