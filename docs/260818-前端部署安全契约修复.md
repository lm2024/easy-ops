# 前端部署安全契约修复（2026-08-18）

## 问题背景

用户反馈：应用管理中部署前端应用后，**重部署会删光部署目录里的所有文件**（包括用户手工放置的无关文件、其他应用目录），存在严重的误删风险。

**根因**：`DeployController` 前端部署分支的旧逻辑
- 目标目录由「解压后目录名 frontendDirName / 前端部署目录 frontendDeployDir / 部署目录本身」三选一决定；
- 未配置 frontendDirName 时，目标目录 = **整个部署目录 deployDir**；
- 部署前执行 `rm -rf {目标目录} && mkdir -p {目标目录}` —— 即**整目录清空**（先备份再清空，但备份的是整个目录）。

用户手工放进部署目录的文件、其他应用目录，随重部署全部丢失。

## 修复方案（新契约）

**固定规则：解压目录名 = zip 文件名去掉扩展名，删除/清理只针对同名文件。**

| 项目 | 旧行为 | 新行为 |
|------|--------|--------|
| 解压目标 | frontendDirName / frontendDeployDir / deployDir 三选一 | `{deployDir}/{zip基础名}/`（固定） |
| 部署前清理 | `rm -rf` 整个目标目录 | 只 `rm -rf {deployDir}/{zip基础名}`，其他文件一律保留 |
| 备份 | 整个目标目录 → `.backup-{ts}` | 仅同名文件夹 → `{zip基础名}.backup-{ts}` |
| 失败还原 | 还原整个目录 | 有备份→还原同名文件夹；无备份→清理失败产生的空目录 |
| zip 校验 | 坏 zip 静默"成功"（空目录） | 未解压出任何文件即报错，触发还原 |
| frontendDirName/frontendDeployDir | 参与路径决策 | 不再参与（列保留，部署忽略） |
| 前端项目 deployDir | 可缺省（退化到版本目录，有守卫） | 必须配置，否则部署报错 |

## 改动文件

### 后端
- `easy-ops/backend/server/src/main/java/com/ops/server/controller/DeployController.java`
  - 删除前端部署目标目录三选一逻辑（frontendDirName / frontendDeployDir）；
  - 前端分支：`cleanTarget = {deployDir}/{zipBaseName}`，仅备份/删除同名文件夹；
  - 新增 `zipBaseName()`（去最后扩展名）与 `trimTrailingSlash()` 工具方法；
  - 失败还原扩展：无备份可还原时清理失败产生的空目录；
  - 保留原有安全校验：非根目录、非系统目录黑名单、不得落在 versions 存档目录内、zip 文件名须为单段。
- `easy-ops/backend/agent/src/main/java/com/ops/agent/controller/FileController.java`
  - `unzipFile` 增加解压条目计数；0 个条目（空包/伪 zip，ZipInputStream 对垃圾内容不抛异常）→ 抛错；
  - `ZipException` 显式转为带路径的 IOException。

### 前端
- `easy-ops/frontend/src/views/ProjectFormView.vue`：移除「解压后目录名」输入框，改为解压规则说明（zip 同名文件夹 + 不删其他文件）；
- `easy-ops/frontend/src/views/ProjectDetailView.vue`：路径说明改为新契约展示。

### 文档
- `AGENTS.md`：新增「前端部署契约（2026-08-18 定稿）」章节。

## 人工验证步骤（用户侧）

1. 用新 server jar 重启 8081（`server/target/ops-platform-server-1.0.0-SNAPSHOT.jar`，注意用你自己的数据目录启动）。
2. docker agent 已运行新 jar，无需重建镜像；若以后用 `docker compose up -d` 重建容器会退回镜像内旧 jar（且本机拉不到 eclipse-temurin 基础镜像），需重新 `docker cp` 新 agent jar。
3. 前端重新构建（`vue-tsc -b && vite build`，构建清空 dist 时用 `npx vite build --emptyOutDir=false` 绕过安全钩子）。
4. 在应用管理的部署目录里放几个随机文件 → 重新部署前端版本 → 确认随机文件还在、仅同名文件夹被替换。
5. 注意契约变化：老项目若曾用「解压后目录名」，升级后新部署会落到 `{deployDir}/{zip名}/`，旧的解压文件夹不会被删（安全），可手动清理。

## 踩坑记录

- **ZipInputStream 不校验魔数**：对非 zip 内容（如文本文件）`getNextEntry()` 返回 null 而非抛异常，导致旧代码"静默成功 + 空目录"。必须靠「解压出 0 个文件即报错」兜底。
- **server 重启后旧 token 失效**：JWT 校验缓存随进程重建，测试中重启 server 后需重新 auto-login 拿新 token。
- **zsh 不分词**：`for spec in "a b c"; do set -- $spec` 在 zsh 下 $spec 不按空格拆分，JSON 拼出 `"port":,` 报 500。写脚本循环构造 JSON 时逐个显式传参。
